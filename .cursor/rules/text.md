# Heroes 5 Mod: Text Guide

## Structure

The mod's text files are located in the `game_texts` folder. There is one subfolder per language, for example `texts-EN` for english, `texts-PL` for polish, etc. Each subfolder contains text files with the same relative path and name, but different content depending on the language.

## Encoding

The text files are encoded in UTF-16 LE.

## Content

The content of the text files consists of regular text, mostly descriptions of game elements. Many text files also contain special tags that are used to format the text in the game. The tags mark the beginning of formatted sections but they do not close. We need to use a new tag to end the previous one.

The list of known tags is as follows:

- `<br>` - line break
- `<h1>`, `<h2>`, `<h3>` - headings
- `<body>` - remove formatting of the text that follows
- `<body_bright>` - remove formatting and make the text brighter
- `<color=COLOR>` - changes the color of the text that follows
- `<color_default>` - resets the color to default
- `<left>`, `<center>`, `<right>` - align the text to the left, center or right
- `<value=ARG>` - insert the value from lua script with the given argument

## Translation

The source of thruth for text files is the english version `texts-EN`.

When translating to other languages, the content of the text files should be the same as in the english version, except for the actual text. The tags should be kept in the same order and with the same arguments. The only difference is that the text between the tags can be translated.

When creating text files for another language, it is recommended to copy the english version and then translate the text, instead of creating a new file from scratch. This way we can be sure that the structure of the file is correct and that all tags are present.

## Glossary

`tools/translation/glossary.yml` lists the names of the mod's game entities (factions, artifacts, skills, spells, creatures, abilities, classes, stats, resources, heroes, specializations, buildings), keyed by English term per category. It is generated by `tools/translation/glossary.py` from the vanilla data paks (`--data`, the game's `data` folder), the extracted vanilla texts (`--texts EN=<folder>`, more languages with `--texts FR=<folder>`...), the mod's `game_data` and `texts-EN`. Don't edit it; rerun the script.

- Names are read through the game tables (`Artifacts.xdb`, `Skills.xdb`, `UndividedSpells.xdb`, `Creatures.xdb` → creature → `CreatureVisual`, `CombatAbilities.xdb`, `HeroClass.xdb`, `HeroAttribute.xdb`, `Mastery.xdb`, `ResourcesInfo.xdb`, the `AdvMapHeroShared` hero files, `TownBuildingSharedStats`) and `Text/Game/Towns/Types/` for the factions.
- **The mod reuses vanilla IDs for different entities** (`ARTIFACT_OGRE_CLUB` is the Cuirass of the Dwarven Kings, many `ABILITY_*` are new abilities). So a term is matched to vanilla by its English name, not its ID: it gets the official translation of the vanilla entity that had the same name (same category first, then any). Terms no vanilla entity had are `new: true`; `ids` lists the mod IDs using the term.
- Mod specialization name files contain the name, the class and the description; only the part before ` - ` on the first line is kept. Placeholder names (`Debug Teleport`, `Not Available`, `Unknown`, `None`, the test heroes `Plate` and `True Tank`, `[...]`, `TODO...`) are skipped.
- Official names can differ a lot from the English: in Russian the factions are Орден Порядка (Haven), Лига Теней (Dungeon), Северные Кланы (Fortress)... and creature names are plural (Ангелы for Angel), so a translation must inflect them to fit the sentence.
- Vanilla heroes that the game doesn't use (Cyrus...) have no name text, so the mod's names for them count as new.
- When the vanilla entities sharing an English name have different translations, the most common one is kept and the script prints a warning. Across categories the same English term can have different translations (vanilla PL: ability "Harm Touch" = Szkodliwy Dotyk, spell = Bolesny Dotyk); that is left as is.
- The vanilla English texts have mislabels the translations don't have: the Holy Charge skill and spell were named "Retaliation Strike" in English but "Święta Szarża" in Polish. A mod term that keeps such a mislabel gets the translation of the real entity. The reverse happens too: vanilla FR names Absolute Protection (skill and spell) "Chance Surnaturelle".
- New terms get `desc`, the start of their description (or biography), as context for their translation.
- New terms are translated in `tools/translation/glossary-new.yml` (`term: {lang: name}`), written by `tools/translation/translate-terms.py` (Claude API, needs `anthropic` and `ANTHROPIC_API_KEY`). The script only adds missing names, never changes one, so the file is reviewed and edited by hand. It sends the whole official glossary as reference (cached), so new names follow the vanilla style. Rerun `glossary.py` to merge the file into `glossary.yml`.
- Errors of the vanilla translations are fixed in `tools/translation/glossary-corrections.yml` (hand-made, `term: {lang: name}`). A correction replaces the official name in every category that has the term; the script warns about a correction whose term is no longer in the glossary.

If the folder where a text file should be written does not exist, it should be created. For example, if we want to create a text file for polish language in the `game_texts/texts-PL/Text/Game/Artifacts/AllSeeingCrown` folder, but the folder does not exist, we should create it first and then create the text file inside it.
